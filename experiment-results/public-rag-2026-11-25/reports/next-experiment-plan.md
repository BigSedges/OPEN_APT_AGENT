# 下一轮实验配置

本轮目标是验证 token 切块、精确原文回查和小规模持久化向量索引，形成全量编码之前的工程依据。原有 512-token 性能探针保留为独立记录。

1. 使用固定 BGE-M3 tokenizer，非 Sigma 长条目按 600 tokens 切分，Sigma 保留完整规则。补齐可从固定下载归档继承的获取时间，记录继承依据。未确认的发布时间保持未知。
2. 连续两次构建并比对输出 SHA-256。对全部切块验证它与上一版片段的原文字符范围一致。保留父片段和原始引用，来源许可和人工审核问题继续列出。
3. 从 tasks-v2 开发题的相关草稿片段及固定哈希抽样中选择 200 个片段，使用本地 BGE-M3、CPU 四线程、batch=2、1024-token 上限。编码前检查长度和截断，保存向量、片段顺序、模型与语料哈希。
4. 使用同一 200 片段和开发查询运行 BM25、向量和 RRF。先报告持久化重载一致性、过滤和向量维度检查，再列出助手草稿标签下的检索指标与时延。子集会减少候选难度，不能据此推出全量性能。
5. 全量编码仍需以语料质量和资源结果为依据，正式人工标签准备与检索工程独立推进。

任务类型草稿标签以 tasks-v2 为准。本轮读取开发集，测试集问题与标签保持封存。所有新增文件保存到 E 盘实验目录。
