### 二、对接 [Sigma多Agent日志调查系统设计(1).md](file:///mnt/c/Users/yue/Documents/xwechat_files/wxid_hldpsy0xkuya22_d2de/msg/file/2026-11/Sigma多Agent日志调查系统设计(1).md#L63-L78) 的 4 个核心落地要点

1. **按数据形态与任务路由，避免能力重叠**
   * **通用异构离线日志（JSONL / Auditd / Sysmon Linux / CSV / XML）** → `Zircolite`
   * **原始 Windows EVTX 深度取证（降噪时间线 + 进程树 + 横向移动 + IOC）** → `Hayabusa` → `Takajo`
   * **规则研发/校验/转换与 Sigma v2 跨事件关联规则** → `pySigma`（静态编译与多后端转换）+ `RSigma`（Lint、关联规则原生执行、MCP 暴露给规则 Agent）
2. **打通 `event_id` 闭环回查**
   * 进 **Zircolite / RSigma** 的规范化 JSONL 直接携带 `event_id`，并确保字段排除配置不将其丢弃；
   * 进 **Hayabusa** 的原始 EVTX 固定开启 `json-timeline -L -p super-verbose`，适配器通过 `Computer + Channel + RecordID` 反查证据库映射为 `event_id`；
   * **Takajo** 产物仅作为上下文线索，由主机 Agent 回查原始证据库后才可写入本案 `evidence_event_ids`。
3. **字段映射与规则版本联动**
   * Zircolite 的 `config.yaml`、pySigma/RSigma 的 `Pipeline`、Hayabusa 的去抽象化规则集需随**规则快照 + 映射版本**一起固化，确保同一案件重跑结果可复现。
4. **关联规则证据保全**
   * RSigma 执行关联规则时，务必保证输入按 UTC 时间有序，且配置 `rsigma.correlation_event_mode`（`refs` 或 `full`）和足够的 `--max-correlation-events`，使每条关联 `Hit` 都能展开为底层组成 `event_ids`；若因截断仅剩聚合计数，则按文档规范降级为线索。
